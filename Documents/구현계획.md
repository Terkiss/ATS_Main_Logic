# 구현 계획 (Implementation Plan) - Milestone 14: Redis Production Integration

## 🔄 진행 상태: PLANNING
> **M14 - Redis Production Integration**
> M12에서 작성된 모의(Simulation) Redis 구조를 실제 StackExchange.Redis 라이브러리와 로컬/원격 Redis 인스턴스 연동 구조로 전환하여 상용 수준의 세션 스토어 및 클러스터 이벤트 버스를 완성합니다.

---

## Phase
Phase 3 — Production-Ready Client & Infrastructure Hardening (두 번째 마일스톤)

## 개요
이전 마일스톤(M12)에서는 메모리 딕셔너리를 활용한 모의 Redis 세션 스토어와 이벤트 버스를 사용했습니다.
이번 마일스톤에서는 실제 `StackExchange.Redis` 클라이언트를 도입하여 로컬/원격 Redis 서버와 연동하고, 다중 게임 서버 노드 간 세션 동기화와 클러스터링 Pub/Sub 메시징을 완성합니다.

## 세부 작업 항목

### 🔄 1. StackExchange.Redis 통합
- **목표**: NuGet 패키지를 추가하고 `ConnectionMultiplexer` 싱글톤 커넥터 연동.
- **내용**:
  - `TeruTeruServer.Runtime` 및 필요한 프로젝트에 `StackExchange.Redis` 의존성 추가.
  - Redis 커넥션 관리 라이프사이클 및 설정 파라미터 구성.

### 🔄 2. RedisSessionStore 실구현
- **목표**: Redis Hash 및 String 데이터 구조를 활용한 실제 분산 세션 관리 구현.
- **내용**:
  - `RedisSessionStore`에서 실제 Redis에 플레이어 세션 정보를 직렬화하여 저장 및 조회.
  - 성능 최적화를 위한 로컬 캐싱 레이어와 Redis 데이터 간의 정합성 유지(Pub/Sub 알림 활용).

### 🔄 3. RedisEventBus 실구현
- **목표**: Redis Pub/Sub을 사용한 분산 서버 인스턴스 간 이벤트 브로드캐스팅 구현.
- **내용**:
  - `RedisEventBus`를 통해 클러스터 전체에 `OnGameEnd`, `OnJoin` 등의 시스템 이벤트를 발행 및 구독 처리.

### 🔄 4. 안전한 장애 전파 (Failover) 및 복구
- **목표**: Redis 일시 단절 및 장애 상황 발생 시 서버 크래시를 방지하고 로컬 백업 세션으로 Fallback 처리.
- **내용**:
  - 예외 처리 회로 차단기(Circuit Breaker) 또는 로컬 캐시 백업 전환 로직 연동.

### 🔄 5. 통합 부하 테스트 및 검증
- **목표**: 다중 서버 인스턴스가 단일 Redis 세션을 공유하여 Reconnect 및 이벤트를 올바르게 송수신하는지 테스트.
- **내용**:
  - 테스트 코드를 통한 로컬 Redis 컨테이너 연동 통합 검증.

## 완료 기준
- **Redis 연동 검증**: Redis 컨테이너 상에서 실제 데이터를 CRUD 하고 다른 세션이 데이터를 조회하는 단위/통합 테스트 통과.
- **릴리즈 Gate**: `verify-release.sh` 통과.
