## Phase
Phase 3 — Production-Ready Client & Infrastructure Hardening (첫 번째 마일스톤)

## 개요
현재 클라이언트 SDK는 단순 데이터 송수신 위주로 작성되어 실전 멀티플레이어 게임 클라이언트 개발 시 많은 로직(예: 보간, 로컬 예측 롤백, 재연결 핸들링)을 밑바닥부터 짜야 하는 병목이 있습니다.
본 마일스톤을 통해 클라이언트가 유예 세션 복구를 직관적으로 수행하도록 `ReconnectAsync` 메서드를 추가하고, 동기화 성능을 극대화하기 위해 위치/상태 보간 유틸리티 및 클라이언트 사이드 예측(CSP) 버퍼를 구현합니다.

## 세부 작업 항목

### 🔄 1. 재연결 기능 (`ReconnectAsync`) 구현
- **목표**: 비정상적인 소켓 단절 시, 세션 유예 토큰(`ReconnectToken`)을 들고 기존의 세션 ID를 그대로 복구하는 플로우 구현.
- **내용**: 
  - `ReconnectProtocol` 모델 정의 및 클라이언트-서버 프로토콜 동기화.
  - `TeruClient.ReconnectAsync(string userId, string reconnectToken)` 구현.
  - 소켓 재설정 및 새로운 ReceiveLoop 구동, 인증 상태 인덱스 복구.

### 🔄 2. Zone / Room 관리 고수준 API 추가
- **목표**: RPC 메서드를 수동 호출하지 않고 직관적으로 공간 이동을 지시하는 전용 메서드 래핑.
- **내용**:
  - `JoinZoneAsync(int zoneId)` / `LeaveZoneAsync()` 구현.
  - `EnterRoomAsync(string roomId)` / `LeaveRoomAsync()` 구현.

### 🔄 3. 클라이언트 보간기 (`SnapshotInterpolator`) 구현
- **목표**: 서버가 보내는 Delta 스냅샷 프레임들의 지연(Latency) 및 지터(Jitter)를 완화하여 자연스러운 렌더링 지원.
- **내용**:
  - 스냅샷 수신 버퍼링 구조 (최근 N개 스냅샷 큐잉).
  - 현재 시각과 렌더링 타겟 타임스탬프를 기준으로 하는 상태 선형 보간(Lerp) 알고리즘 구현.
  - 바이너리 Delta 스냅샷 전용 파서 유틸리티 포함.

### 🔄 4. 클라이언트 예측 버퍼 (`ClientPredictionBuffer`) 구현
- **목표**: 로컬 클라이언트 입력을 즉각 반영(CSP)하고, 서버 판정 도래 시 오차를 롤백 후 재시뮬레이션하는 편의 프레임워크 제공.
- **내용**:
  - 아직 승인(Ack)되지 않은 로컬 입력 리스트와 예측 상태 기록.
  - 서버 스냅샷 수신 시, 해당 Tick의 예측값과 비교하여 오차가 임계치(Epsilon)를 넘을 경우 상태 롤백 후 잔여 입력 재적용(Replay).

## 완료 기준
- **재연결 검증**: 테스트 환경에서 연결 강제 종료 후 5초 이내에 `ReconnectAsync`를 호출해 기존 로비/룸 세션 상태가 그대로 복구되는지 검증.
- **보간기 동작**: 모의 패킷 핑 100ms 지터 환경에서 오브젝트의 위치 정보가 갑자기 순간이동(Teleport)하지 않고 부드럽게 이어지는지 테스트 코드로 증명.
- **릴리즈 Gate**: `verify-release.sh` 통과.
