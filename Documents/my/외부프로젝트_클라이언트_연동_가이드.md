# 외부 프로젝트에서 TeruTeruServer 클라이언트 연동하기

> 이 문서는 TeruTeruServer 엔진과 통신하는 클라이언트를 **외부 프로젝트**(Unity, MAUI, 콘솔 앱 등)에서 만들 때 필요한 내용을 정리한 것입니다.

---

## 1. 가져가야 할 DLL (빌드 결과물)

외부 프로젝트에 아래 **두 개의 DLL만** 참조로 추가하면 됩니다.

| DLL | 역할 |
|---|---|
| `TeruTeruServer.SDK.dll` | 공용 규약: 어트리뷰트, 열거형, 데이터 모델, 인터페이스 |
| `TeruTeruServer.Client.dll` | 클라이언트 통신 핵심: `TeruClient`, P2P 관리 등 |

> **⚠️ 주의:** `TeruTeruServer.Cli` 프로젝트는 **서버를 구동하는 호스트**이므로 클라이언트 프로젝트에서는 필요 없습니다.

---

## 2. 자주 쓰는 using문

```csharp
using TeruTeruServer.Client;          // TeruClient 클래스
using TeruTeruServer.SDK.Attributes;  // [Rpc], [Protocol] 어트리뷰트
using TeruTeruServer.SDK.Enums;       // ProtocolSelect, SendType 등 열거형
using TeruTeruServer.SDK.Protocol;    // YoloDetectResult 등 프로토콜 데이터 모델
```

## 3. 클라이언트 구현 순서

### 3.1 수신 로직 클래스 (Handler) 작성

서버로부터 메시지를 받을 클래스를 만들고, 메서드에 어트리뷰트를 붙입니다.

```csharp
using System;
using TeruTeruServer.SDK.Attributes;
using TeruTeruServer.SDK.Enums;
using TeruTeruServer.SDK.Protocol;

public class MyClientLogic 
{
    // 서버가 "OnServerMessage"라는 RPC를 보내면 자동 실행
    [Rpc("OnServerMessage")]
    public void OnMessage(string msg) 
    {
        Console.WriteLine($"[서버 알림]: {msg}");
    }

    // 서버가 특정 Protocol enum으로 데이터를 보냈을 때 자동 실행
    [Protocol(ProtocolSelect.QueueCountCommand)]
    public void OnQueueCountUpdate(YoloDetectResult result)
    {
        Console.WriteLine($"[데이터 수신]: {result.DetectionResult}");
    }
}
```

### 3.2 TeruClient 초기화 및 서버 연결

```csharp
using System;
using System.Threading.Tasks;
using TeruTeruServer.Client;

class Program
{
    static async Task Main(string[] args)
    {
        // 1. 서버 IP와 Port로 클라이언트 인스턴스 생성
        using var client = new TeruClient("127.0.0.1", 3000);
        
        // 2. 수신 로직 등록 (이 한 줄로 수신 라우팅 완료)
        client.RegisterLogic(new MyClientLogic());

        // 3. 이벤트 핸들러 연결
        client.OnLog += Console.WriteLine;
        client.OnDisconnected += () => Console.WriteLine("서버와 연결 끊김");

        // 4. 서버에 접속
        if (!await client.ConnectAsync())
        {
            Console.WriteLine("접속 실패");
            return;
        }

        // 5. 로그인 (내부적으로 JWT 발급 + UDP P2P 자동 초기화)
        if (await client.LoginAsync("user_id", "user_password"))
        {
            Console.WriteLine("로그인 성공!");

            // 6. 서버에 RPC 호출
            var result = await client.InvokeRpcAsync<string>("Echo", "안녕하세요!");
            Console.WriteLine($"RPC 응답: {result}");
        }

        Console.ReadLine(); // 프로그램 유지
    }
}
```

## 4. RPC 양방향 통신 정리

### 4.1 클라이언트 → 서버 호출

**서버 측 (로직 플러그인에서):**
```csharp
[Rpc("Echo")]
public string Echo(string message, PacketContext context)
{
    return $"서버 응답: {message}";
}
```

**클라이언트 측 (외부 프로젝트에서):**
```csharp
string result = await client.InvokeRpcAsync<string>("Echo", "Hello!");
// result == "서버 응답: Hello!"
```

### 4.2 서버 → 클라이언트 푸시

**클라이언트 측 (외부 프로젝트에서):**
```csharp
public class MyClientLogic 
{
    [Rpc("OnServerMessage")]
    public void ReceiveMessage(string msg) 
    {
        Console.WriteLine($"서버 푸시: {msg}");
    }
}

// 반드시 RegisterLogic으로 등록해야 동작함
client.RegisterLogic(new MyClientLogic());
```

**서버 측 (로직 플러그인에서):**
```csharp
await session.SendRpcAsync("OnServerMessage", "서버 점검 5분 뒤 시작");
```

> **핵심:** 양쪽의 `[Rpc("이름")]` 문자열 키가 정확히 일치해야 합니다.

## 5. SDK 자동화 기능 (알아서 처리되는 것들)

| 기능 | 설명 |
|---|---|
| **P2P 홀펀칭** | `LoginAsync()` 성공 시 내부에서 UDP 소켓 바인딩 + NAT 정보 서버 등록 자동 수행 |
| **릴레이 폴백** | 홀펀칭 실패 시 자동으로 서버 릴레이 모드로 전환 |
| **재연결 (Reconnect)** | 네트워크 끊김 시 유예 기간(Grace Period) 내 토큰으로 상태 유지하며 재연결 가능 |
| **패킷 라우팅** | `RegisterLogic()` 한 번으로 어트리뷰트 기반 자동 매핑 완료 |

## 6. SDK 주요 폴더 구조 참고

### `TeruTeruServer.SDK/Interfaces/` — 서버 인프라 규약
- `ISessionManager`: 클라이언트 연결 수명 주기 관리
- `IProtocolRouter`: 패킷을 적절한 핸들러로 라우팅
- `IMessageSender`: 클라이언트에게 패킷 전송
- `ICryptoService`: 암호화/복호화, HMAC 서명
- `IGameLoop`: 실시간 틱 루프
- `IZoneManager`: 존(Zone) 관리 및 인스턴스 생성
- `IAoIFilter`: 관심 영역(AoI) 필터링
- `IRoomBroadcaster`: 방/그룹 단위 브로드캐스팅
- `IEventBus`: Pub/Sub 이벤트 버스
- `IClusterRegistry`: 클러스터 노드 관리
- `ISessionStore`: 세션 저장소 추상화 (Redis 등)

### `TeruTeruServer.SDK/GameEngine/` — 게임 로직 도구 모음
- `RttTracker`: 핑(RTT) 및 지터(Jitter) 이동 평균 추적
- `SnapshotBuffer`: 과거 게임 상태 링 버퍼 (지연 보상용)
- `HitValidationModels`: 피격 검증 데이터 구조
- `GameInput` / `InputQueue`: 클라이언트 입력 처리 (CSP 지원)
- `GameEntity` / `ServerEntity`: 게임 객체 기본 뼈대
- `WorldState` / `RoomState`: 틱 기준 상태 스냅샷
- `WorldHierarchyModels`: 월드-존-인스턴스 계층 구조
- `MatchEntry`: 매치메이킹 대기열 정보
